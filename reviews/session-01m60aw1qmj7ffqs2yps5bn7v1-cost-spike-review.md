## Verdict: RESUME (on track)

The paused session's plan is correct and its target is the right prerequisite for the computer-ply work already merging on the epic-story branch. Nothing is stranded, so resume rather than cancel, with these constraints:

1. **Extract, don't rewrite.** Move the existing post-authorization block of `SubmitMoveAsync` (from the `TryApplyMove` call at line 94 through the notifier call) into a single private helper, e.g. `ApplyPlyAsync(Game game, PlayerColor color, string fromSquare, string toSquare, PromotionPieceType? promotion)`, **byte-for-byte in behavior**. Keep slot-token resolution (`ResolveSlotToken`), the `Status != Active` guard and the `NotYourTurnException` guard in the human-facing method — those are human-only concerns and must not silently apply to engine plies.
2. **Preserve observable behavior exactly.** The helper must keep the same exception types (`IllegalMoveException`, `PromotionRequiredException`), the same `MoveNumber` computation via `game.Moves.Max(...)`, the same `ParseHalfmoveClock`-derived clock, and the same terminal-status ordering (checkmate → stalemate → fifty-move). Verify with the existing `GameServiceTests` suite unchanged and green first, before adding any test that exercises the helper indirectly.
3. **Add tests only through the public seam.** Since the helper is private, cover it via `SubmitMoveAsync` tests (which already exist) plus, once the computer ply lands, tests that show both paths producing identical `Move` records and terminal transitions. Do not add a test-only public accessor.
4. **Do not touch the client or the API surface** in this increment — that is the exact boundary the prior attempt crossed and was reverted for.
5. **Budget control** (the reason for the pause): commit the extraction as its own single-purpose green commit immediately after the refactor, before starting any computer-ply orchestration, so a future spike cannot strand a half-extracted method.
